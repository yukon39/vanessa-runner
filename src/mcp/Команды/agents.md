# Команды MCP

Руководство по созданию MCP-инструментов, выполняющих CLI-подкоманды vanessa-runner.

## Связанные файлы

```
src/cli/{Группа}_Подкоманды/Подкоманда*.os   — источник истины (логика команды)
src/mcp/КонтекстВанессаMCP.os               — наборы опций сессии (задаются отдельными tools)
src/mcp/НаборыОпций/                          — MCP-tools для наборов опций (см. agents.md)
src/mcp/Команды/
  agents.md                                   — эта инструкция
  {Группа}_Подкоманды/Инструмент*.os          — MCP-инструменты команд
```

Каждый файл `Инструмент*.os` в этой папке — один MCP-tool, делегирующий выполнение существующей CLI-подкоманде.

## Архитектура

MCP-сервер разделяет настройку и выполнение:

1. **Наборы опций** (`*-options` tools) — устанавливают параметры подключения, платформы, СУБД и т.д. в `КонтекстВанессаMCP` на время сессии.
2. **Команды** (`infobase-init` и др.) — выполняют действие, переиспользуя CLI-подкоманду с опциями из контекста.

```
LLM → connection-options, platform-options, …  →  КонтекстВанессаMCP
LLM → infobase-init { source: "…" }            →  ПодкомандаInfobaseInit.ВыполнитьДействие()
```

Инструмент команды **не дублирует** параметры наборов опций — они уже заданы через соответствующие `*-options` tools.

Именование:

- MCP tool: `{группа}-{подкоманда}` (kebab-case / dash-style, группа — имя родительской команды без префикса `Команда`)
- Параметры tool: `Имя` из `&Опция` / `&Аргумент` CLI; если в CLI указаны короткая и полная формы (`s src`, `R recursive`) — в MCP только **полная** (`src`, `recursive`)
- Файл: `Инструмент{ИмяПодкоманды}.os` (PascalCase, как класс CLI)
- Каталог: зеркалирует `src/cli/{Группа}_Подкоманды/`
- Описание tool: глагол в инфинитиве, понятный для LLM (`Инициализировать информационную базу`)

> **Правило:** kebab-case (dash-style) для имён tools — как в CLI. Параметры — как в CLI, но без коротких алиасов (`s src` → `src`). Не использовать snake_case и underscore.

Пример соответствия CLI → MCP:

| CLI | MCP tool |
|-----|----------|
| `КомандаInfobase` + `init` | `infobase-init` |
| `КомандаInfobase` + `restore-dt` | `infobase-restore-dt` |
| `КомандаCluster` + `session` + `lock` | `cluster-session-lock` |
| `КомандаCluster` + `jobs` + `unlock` | `cluster-jobs-unlock` |

## Соответствие CLI → MCP

### Параметры команды

Только собственные `&Опция` / `&Аргумент` подкоманды копируются в инструмент:

| CLI | MCP |
|-----|-----|
| `&Опция(Имя, Описание)` | `&ПараметрИнструмента(Имя, Описание)` — при `Имя = "s src"` использовать `"src"` |
| `&ТСтрока` | `string` (тип по умолчанию) |
| `&Флаговый` | `Тип = "boolean"` |
| `&ТПеречисление` | `Тип = "string"`, к описанию дописать допустимые значения |

`&НаборОпций` **не** переносятся в инструмент команды — они берутся из `КонтекстВанессаMCP`.

Имя переменной совпадает с полем CLI-подкоманды (`Источник`, не `source`).

### Зависимости

Скопировать из CLI-подкоманды все `&Пластилин`-поля (сервисы), кроме `&Лог` — лог задаётся через рефлектор.

## Структура инструмента

Эталон — `ИнструментInfobaseInit.os`.

```bsl
// BSLLS:MissingVariablesDescription-off Поля &ПараметрИнструмента - описания заданы в аннотациях.

&Пластилин("КонтекстВанессаMCP")
Перем КонтекстMCP;

&Пластилин
Перем СервисПлатформы;

&Пластилин
Перем СервисКонфигурации;

&Пластилин
Перем СервисЗаполненияПараметров;

&Пластилин
Перем СервисРасчетаИнкремента;

&ПараметрИнструмента(Имя = "source", Описание = "Источник конфигурации (каталог исходников, *.cf или *.dt файл)")
Перем Источник;

&Инструмент(Имя = "infobase-init", Описание = "Инициализировать информационную базу")
Процедура ПриСозданииОбъекта()
КонецПроцедуры

&ВыполнениеИнструмента
Функция ИнициализироватьИнформационнуюБазу() Экспорт

	Команда = Новый ПодкомандаInfobaseInit();
	ПрименитьПараметрыККоманде(Команда);
	Команда.ВыполнитьДействие();

	Возврат "Инициализация информационной базы завершена";

КонецФункции
```

## Логика выполнения

### 1. Создание и делегирование

```bsl
Команда = Новый ПодкомандаInfobaseInit();
ПрименитьПараметрыККоманде(Команда);
Команда.ВыполнитьДействие();
```

Бизнес-логика остаётся в CLI-подкоманде. Инструмент MCP — тонкий адаптер.

### 2. Применение параметров через рефлектор

Процедура `ПрименитьПараметрыККоманде` переносит в экземпляр подкоманды всё, что CLI заполняет через DI и `СервисЗаполненияПараметров.Заполнить()`:

```bsl
Процедура ПрименитьПараметрыККоманде(Команда)

	Рефлектор = Новый Рефлектор();

	// Сервисы (из &Пластилин CLI-подкоманды)
	Рефлектор.УстановитьСвойство(Команда, "Лог", Логирование.ПолучитьЛог("vrunner"));
	Рефлектор.УстановитьСвойство(Команда, "СервисПлатформы", СервисПлатформы);
	Рефлектор.УстановитьСвойство(Команда, "СервисКонфигурации", СервисКонфигурации);
	Рефлектор.УстановитьСвойство(Команда, "СервисЗаполненияПараметров", СервисЗаполненияПараметров);
	Рефлектор.УстановитьСвойство(Команда, "СервисРасчетаИнкремента", СервисРасчетаИнкремента);

	// Наборы опций (из КонтекстВанессаMCP)
	Рефлектор.УстановитьСвойство(Команда, "ОпцииПодключения", КонтекстMCP.НаборОпцийПодключения());
	Рефлектор.УстановитьСвойство(Команда, "ОпцииПлатформы", КонтекстMCP.НаборОпцийПлатформы());
	Рефлектор.УстановитьСвойство(Команда, "ОпцииСУБД", КонтекстMCP.НаборОпцийСУБД());
	Рефлектор.УстановитьСвойство(Команда, "ОпцииНастроек", КонтекстMCP.НаборОпцийНастроек());

	// Собственные параметры команды (из &ПараметрИнструмента)
	Если Источник <> Неопределено Тогда
		Рефлектор.УстановитьСвойство(Команда, "Источник", Источник);
	КонецЕсли;

КонецПроцедуры
```

Правила:

- Каждый `&НаборОпций` CLI-подкоманды → геттер `КонтекстMCP.НаборОпций*()` с **тем же** именем свойства (`ОпцииПодключения`, не `НаборОпцийПодключения`).
- Каждый `&Пластилин` CLI-подкоманды → `Рефлектор.УстановитьСвойство` с тем же именем.
- Каждый `&ПараметрИнструмента` → блок `Если ... <> Неопределено`.
- Имена свойств — как в CLI-подкоманде (регистр и транслит).

### 3. Ответ

Команды возвращают **строку** с результатом выполнения (не `Соответствие`, как у `*-options`):

```bsl
Возврат "Инициализация информационной базы завершена";
```

Текст должен быть информативным для LLM. Ошибки пробрасываются как исключения — MCP-сервер вернёт `isError: true`.

## Создание

Когда в `src/cli/{Группа}_Подкоманды/` появилась новая `Подкоманда*`:

1. Убедиться, что все используемые `&НаборОпций` уже покрыты tools в `src/mcp/НаборыОпций/` (см. [agents.md](../НаборыОпций/agents.md)).
2. Создать каталог `src/mcp/Команды/{Группа}_Подкоманды/` (если ещё нет).
3. Создать `Инструмент{ИмяПодкоманды}.os` по эталону.
4. Скопировать `&Пластилин`-сервисы из CLI-подкоманды.
5. Скопировать собственные `&Опция` / `&Аргумент` → `&ПараметрИнструмента`.
6. Реализовать `ПрименитьПараметрыККоманде` — сервисы, наборы опций, параметры команды.
7. Реализовать `&ВыполнениеИнструмента` — создание подкоманды, применение параметров, `ВыполнитьДействие()`, возврат строки.
8. Добавить строку в реестр этого файла.

Файл подхватывается автоматически через `package-loader.os` (рекурсивное сканирование `*.os`).

MCP-приложение (`src/mcp.os`) должно подключать `#Использовать "./core/Приложение"` — иначе не резолвится `СервисОкружения`.

## Актуализация

При изменении `src/cli/{Группа}_Подкоманды/Подкоманда*.os`:

| Изменение в CLI | Действие |
|-----------------|----------|
| Добавлен `&Опция` / `&Аргумент` | `&ПараметрИнструмента` + блок в `ПрименитьПараметрыККоманде` |
| Изменены `Имя` / `Описание` опции | Синхронизировать в инструменте |
| Изменён тип опции | Обновить `Тип` в `&ПараметрИнструмента` |
| Добавлен `&НаборОпций` | Строка в `ПрименитьПараметрыККоманде` + tool в `НаборыОпций` (если новый набор) |
| Добавлен `&Пластилин` | Строка в `ПрименитьПараметрыККоманде` |
| Удалена `&Опция` | Удалить из инструмента |
| Переименован класс подкоманды | Обновить `Новый ...()` и имя файла |

Чеклист:

- [ ] Все `&Пластилин` CLI-подкоманды перенесены в инструмент
- [ ] Все `&НаборОпций` CLI-подкоманды подключены через `КонтекстMCP`
- [ ] Все собственные `&Опция` / `&Аргумент` → `&ПараметрИнструмента`
- [ ] Имена параметров совпадают с CLI (полная форма, без коротких алиасов); описания совпадают
- [ ] Имена свойств в `ПрименитьПараметрыККоманде` совпадают с CLI
- [ ] Каждый параметр команды — блок `Если ... <> Неопределено`
- [ ] `ВыполнитьДействие()` вызывается без дублирования бизнес-логики
- [ ] Ответ — информативная строка
- [ ] Реестр обновлён

## Проверка

```powershell
echo '{"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}}' | oscript src/mcp.os
```

В ответе должен появиться новый tool с актуальным `inputSchema.properties`.

Типовой сценарий вызова:

```
1. connection-options  { ibconnection: "…" }
2. platform-options    { v8version: "8.3.24" }
3. infobase-init       { source: "src/cf" }
```
